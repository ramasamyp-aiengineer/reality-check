CORROBORATED

2 or more independent supports

Confidence, factor by factor

Every factor is shown in the report with the evidence behind it.

30 rules, 13 families

Four finding kinds: contradiction, gap, signal, support, each with a severity and the evidence ids behind it.

Decision: Do not proceed · Proceed with caution · Wait and verify · Safe to proceed.

Responsible wording. Verdicts describe evidence status, never accusations. Reality Check never labels a person or company "fraud". Explanations are available in English, Hindi and Tamil.

Technical depth · the stack in seven layers

Built like a product, not a prototype.

Layer 4 · orchestration and typed signals

A typed DAG executor with parallel waves and live events.

Loan forward check, as executed

Events are persisted, then streamed over Server-Sent Events. The UI replays them on reconnect.

Validation before cost: cycles, unknown agents, duplicate node ids, dangling edges and a missing Intent agent are all rejected. Then estimate_searches prices the graph against the workspace budget.

# every agent is a declared, costed contract
AgentSpec(
  id="app_identity", category="evidence",
  engines=["google_play", "google_play_product"],
  consumes=["ClaimSet"], produces=["AppProfile"],
  est_searches=2,
  proves="Who really publishes the app...",
)
# rules declare the signals they need
@rule("registry.not_listed",
      "Not found in the regulator registry",
      ("RegistryStatus", "ClaimSet"), ...)
def not_listed(bag: SignalBag) -> list[Finding]: ...

Agents only touch SerpApi through ctx.search(), and only read upstream results from a typed Pydantic SignalBag.

Layer 1 · the SerpApi gateway

One client for 16 engines: budgeted, cached, redacted, receipted.

live

Real calls, with a SQLite response cache keyed by a params hash that excludes the key.

record

Live calls, and each response is written to fixtures with the key scrubbed.

replay

Replays fixtures by exact params hash, then by engine plus query. Never touches the network.

The real RBI lending-app list, matched safely against look-alikes.

FETCH

A script downloads RBI's public export. Grievance contacts are dropped; only app, owner, lender, platform and link are kept.

→
NORMALISE

Merged cells are forward-filled, links cleaned, names normalised.

→
MATCH

Play package id first. Then a name match on distinctive words, ignoring generic ones like "instant", "loan", "rupee".

→
GUARD

Fuzzy threshold 86. Generic-only names need 95. "Kredit Bee" never matches "Kredit Rupee".

→
RULES

Listed, not listed, or lender mismatch, each with its evidence.

Careful wording, straight from the rule: "Not being listed does not prove wrongdoing, but legitimate lenders must report their apps to RBI." The report then links to RBI's own DLA directory and the Sachet portal.

Layer 5 · trust, security and responsible AI

Enterprise-grade by default, even for a solo build.

Key never leaves

The SerpApi key is never logged or sent to the browser. Saved keys use AES-256-GCM bound to the workspace.

Redaction everywhere

Keys are stripped from errors, receipts, cache keys, fixtures and server logs. Tests assert it.

Strong auth

Argon2id passwords, lockout after failures, rate-limited auth, generic errors.

Sessions and CSRF

HttpOnly SameSite=Strict cookies and a double-submit CSRF token on every write.

Roles and audit

Admin, analyst and viewer roles. An audit log of sign-ins, keys, runs and tokens, with no secrets.

SSRF guard

User URLs must be public. Private, loopback and metadata addresses are rejected, even after DNS.

Prompt-injection hygiene

Search results are fenced as untrusted data. The LLM cannot start searches or change a verdict.

Hardened headers

CSP, HSTS, frame denial, nosniff, Referrer- and Permissions-Policy. Hashed, revocable API tokens.

Session-only keys by default. A pasted key lives only in the session; saving it is opt-in. Demo mode never touches the network, so judges can run everything offline.

Layer 6 · a platform, not just an app

Watches, MCP, REST, and any open-source model.

Open-source and local LLMs

Any Pydantic AI provider, including Ollama, LM Studio or llama.cpp. A 3B model on a laptop is enough, because rules decide. If the model fails, every step falls back to rules.
